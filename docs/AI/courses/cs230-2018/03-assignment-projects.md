# CS230 课程项目笔记：昼夜分辨与人脸验证

> 本页整理 CS230 课程中两个经典小项目的设计思路：昼夜图像二分类与人脸验证，重点在于从问题描述到模型设计的完整推理过程。

## 学习目标

- 学会把业务问题翻译成“数据 → 输入 → 输出 → 架构 → 损失”五要素；
- 理解二分类与相似度比较两种任务在架构上的差异；
- 能够为一个小项目写出清晰的实验设计文档。

## 1 项目一：昼夜分辨

### 1.1 问题描述

给一张图像，输出它是白天（1）还是黑夜（0）。

### 1.2 五要素拆解

| 要素 | 设计 |
| --- | --- |
| Data | 约 10,000 张图像，按 80%/20% 划分训练集与验证集，保证两类数量均衡 |
| Input | 像素图像，分辨率 $(64, 64, 3)$，在不损失效果的前提下尽量降低分辨率 |
| Output | 标签 0/1；最后一层用 sigmoid 输出概率 |
| Architecture | 浅层神经网络即可（任务简单、数据量有限） |
| Loss | 对数似然损失（交叉熵），分类问题的标准选择 |

**为什么要降分辨率**：减少输入维度 = 减少参数 = 更少过拟合、更快训练。小模型在简单任务上往往比大模型更稳。

### 1.3 数据均衡

训练集中白天/黑夜数量应大致相同。如果不均衡，模型会倾向预测多数类，准确率虚高。

## 2 项目二：人脸验证

### 2.1 问题描述

学校希望在食堂、健身房等设施用人脸验证确认学生身份：系统看到“当前人 + 声称的 ID”，判断是否为本人。

### 2.2 与分类的区别

人脸验证不是训练时见过的固定类别集合，而是**一对一的相似度比较**：

- 输入：当前采集图像 + 该 ID 的注册照片；
- 输出：`y = 0`（是本人）或 `y = 1`（不是本人）；
- 思路：用网络把两张图编码为向量，计算距离（或余弦相似度），距离小于阈值判定为本人。

### 2.3 架构设计要点

- 可以使用预训练卷积网络提取特征（迁移学习）；
- 训练目标常用**三元组损失**：让同一人的向量距离小、不同人的向量距离大；
- 分辨率建议 $(400+, 400+, 3)$，保证面部细节清晰；
- 验证阈值需要根据误接受率（FAR）与误拒绝率（FRR）权衡。

## 3 通用设计清单

无论项目大小，动手前先写清楚：

1. Goal：一句话说明要解决什么问题；
2. Data：数据量、来源、划分方式、类别是否均衡；
3. Input：输入形式与分辨率，能否降维；
4. Output：输出是什么，用什么激活函数；
5. Architecture：模型复杂度与任务是否匹配；
6. Loss：为什么选这个损失，有没有替代；
7. Baseline：先用一个最简单的模型（逻辑回归/浅层网络）跑通。

## 4 动手练习

1. 用 `make_moons` 或自拍/风景照片构造一个昼夜数据集，按五要素模板写出设计文档再训练；
2. 比较浅层网络（1 个隐藏层）与逻辑回归在本任务上的准确率差异；
3. 对人脸验证，尝试用余弦相似度替代欧氏距离，画出 FAR/FRR 随阈值变化的曲线；
4. 写一个“设计审查”清单，拿一篇课程作业互相检查是否五要素齐全。
